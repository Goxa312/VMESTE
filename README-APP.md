# Вместе

Веб-приложение для совместного просмотра по прямым ссылкам и страницам Киного через расширение. Русский интерфейс, адаптивная библиотека, комнаты до 12 человек, синхронное управление ведущего, чат и реакции. Поддерживаются MP4, WebM и HLS (.m3u8); конкретные кодеки должны поддерживаться браузером.

## Использование

1. Нажмите «Добавить видео», вставьте прямую HTTPS-ссылку и выберите раздел: фильм, сериал или аниме.
2. Откройте карточку и создайте комнату.
3. Передайте друзьям ссылку из комнаты. Каждый вводит имя и нажимает «Войти в просмотр», чтобы разрешить звук.
4. Ведущий запускает, останавливает и перематывает общий плеер. Громкость у каждого участника своя.

Прямое видео загружается непосредственно с указанного источника. Для HLS источник должен разрешать CORS. Библиотека хранится на сервере; ключ доступа к ней и права ведущего сохраняются в текущем браузере. Очистка данных браузера сбрасывает этот доступ. Комнаты перестают быть доступны через 7 дней; ссылки-приглашения следует передавать только участникам.

## Обычные ссылки Киного

Страницы фильмов и сериалов с `kinogo.my` принимаются в библиотеку и комнаты. Для них используется расширение Chrome/Edge: видео открывается на исходном сайте в отдельной вкладке, а комната передаёт запуск, паузу и перемотку ведущего. Расширение устанавливается каждым участником; инструкции доступны по адресу `/kinogo-extension` и в `extension/kinogo/README.md`.

После запуска фильма на Киного нажмите «Подключить это видео» в панели расширения, после рекламы. Выбирайте одинаковую версию фильма и перевод. Вкладка комнаты должна оставаться открытой. Поддерживаются `kinogo.my` и наблюдаемый плеер `kinogomy.stravers.live`; другие сайты и плеерные домены требуют отдельной интеграции. Недоступность видео на самом сайте, DRM и ограничения доступа не обходятся.

Расширение не получает токен участника или чат: авторизованные запросы выполняются во вкладке комнаты. Сборка настроена на локальные адреса приложения; для разных компьютеров требуется общий доступный сервер и настройка его origin в расширении.

## Развёртывание в Cloudflare Workers

### Что загрузить в репозиторий

Загрузите содержимое папки `vmeste` в корень репозитория: `package.json` должен лежать в корне, рядом с `app`, `components`, `lib`, `db`, `drizzle`, `public`, `extension`, `scripts`, `worker`, `hooks`, `vendor` и конфигурационными файлами. Сохраните скрытую папку `.openai` — её `hosting.json` используется при сборке. `.gitignore` и `package-lock.json` также нужны.

Не загружайте `node_modules`, `dist`, `.next`, `.vinext`, `.wrangler`, `.sites-runtime`, `.git`, `outputs`, `.env*` и `.dev.vars*`. В `.wrangler` находится локальная база, а не исходники; онлайн-база создаётся отдельно. Git уже исключает эти рабочие файлы через `.gitignore`.

### Подготовка D1

1. В Cloudflare откройте **Storage & databases → D1** и создайте базу `vmeste-db`.
2. Скопируйте её **Database ID** и вставьте в `wrangler.jsonc` вместо `00000000-0000-4000-8000-000000000000`. Имя привязки оставьте `DB`. Database ID — идентификатор, не секретный ключ.
3. Сохраните изменение в репозитории. `npm run deploy` проверяет, что вместо заглушки задана настоящая база; перед публикацией применяет ещё не выполненные SQL-миграции из `drizzle`.

### Подключение GitHub к Workers

В **Workers & Pages** создайте **Worker**, подключите репозиторий и укажите:

| Настройка | Значение |
| --- | --- |
| Worker name | `vmeste` (совпадает с `name` в `wrangler.jsonc`) |
| Root directory | Корень репозитория; если загрузили внешнюю папку целиком — `vmeste` |
| Build command | `npm run build` |
| Deploy command | `npm run deploy` |
| Build variable `NODE_VERSION` | `24` |
| Build variable `VMESTE_APP_ORIGIN` | Публичный HTTPS-адрес сайта без пути, например `https://vmeste.your-account.workers.dev` |

Workers Builds устанавливает npm-зависимости по `package-lock.json`. Токен сборки должен иметь права **Workers Scripts: Edit** и **D1: Edit** для вашего аккаунта: deploy-команда не только публикует Worker, но и применяет миграции. Настройте этот токен в Cloudflare; не добавляйте его в репозиторий.

Если публичный адрес пока неизвестен, первый deploy можно выполнить без `VMESTE_APP_ORIGIN`: сайт заработает для прямых видео. После получения адреса добавьте переменную **сборки**, запустите новую сборку и скачайте расширение со страницы `/kinogo-extension`. Без этой переменной ZIP поддерживает только localhost.

`npm run build` автоматически собирает ZIP расширения. При заданном `VMESTE_APP_ORIGIN` архив включает разрешение и проверки для конкретного адреса сайта. Исходная установленная локальная копия не меняется. Каждый участник скачивает архив с опубликованного сайта и устанавливает/обновляет расширение в своём браузере.

Папки `dist/client` и `dist/server` создаёт сборка. Публикуется Worker из `dist/server/wrangler.json` вместе со статическими файлами. Дополнительное поле «каталог вывода» для этого сценария не нужно.

Для первого запуска используйте новую D1-базу. `migrations apply` хранит историю и не повторяет применённые миграции. Если вы уже вручную импортировали эту схему в онлайн-базу, сначала согласуйте историю миграций — повторное создание таблиц завершится ошибкой.

Локальные фильмы в библиотеке, комнаты и чат автоматически в онлайн-базу не переносятся. На публичном сайте создайте новую комнату и отправьте друзьям её HTTPS-ссылку.

Официальные инструкции: [Workers Builds](https://developers.cloudflare.com/workers/ci-cd/builds/configuration/), [миграции D1](https://developers.cloudflare.com/d1/reference/migrations/).

## Разработка

Node.js 22.13+ и npm. Проект использует Vinext/React, Cloudflare Workers и D1. Схема находится в `db/schema.ts`; проверенная миграция — `drizzle/0000_solid_ben_grimm.sql`.

```sh
npm ci
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_solid_ben_grimm.sql
npm run dev
```

Применяйте локальную миграцию только один раз на новую базу. Локальные данные из `.wrangler` не публикуются. Sites применяет миграции к отдельной серверной базе при публикации.

## Проверки

```sh
npx tsc --noEmit
node --test tests/kinogo-extension.test.mjs
node scripts/package-kinogo-extension.mjs
node tests/integration.mjs
npm run build
```

Для интеграционных проверок нужен запущенный сервер на `http://127.0.0.1:5173`; другой адрес можно задать через `TEST_BASE_URL`. Проверки создают тестовые комнаты в указанной базе. Проверяются две роли, позднее подключение, общая временная шкала, конкурирующие изменения, чат, вместимость и изоляция библиотек.

Синхронизация использует серверную позицию, время обновления и версию состояния. Клиенты опрашивают сервер примерно раз в секунду, учитывают разницу часов и корректируют локальное воспроизведение. Задержка передачи действий зависит от сети. При обрыве связи интерфейс показывает переподключение; после восстановления состояния сходятся снова. Переключать фильм может только ведущий.
