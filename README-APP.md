# Together Tonight

Частный кинозал на Cloudflare Workers. До 12 участников могут смотреть загруженный фильм, видео по прямой ссылке или показ вкладки. Для входа гостю нужна только ссылка на комнату.

## Использование

1. На главной рядом с «Наш список» нажмите «Создать комнату», вставьте адрес публичной страницы или самого видео, введите своё имя и нажмите «Создать комнату». Страницу откройте через «Открыть сайт», затем нажмите «Показать вкладку» и выберите вкладку фильма. Передача звука включается отдельно. Защищённые плееры могут блокировать захват. Ссылки на MP4, WebM, MOV и HLS открываются сразу в общем плеере. Для прямого адреса без расширения выберите его тип в дополнительных настройках.
2. Во вкладке «С компьютера» формы «Создать комнату» можно загрузить MP4, WebM и MOV с поддерживаемыми браузером кодеками. После загрузки участники смотрят файл из хранилища комнаты, могут присоединиться позже и видят перемотку ведущего. Если файл больше лимита хранилища, кнопка «Показать файл из браузера» переключает на прямую передачу. При прямой передаче ведущему нужно оставаться в комнате и после перезагрузки выбрать файл повторно.
3. «Пригласить друга» копирует ссылку. Гость вводит имя, затем нажимает «Войти в просмотр» в общем плеере или «Смотреть трансляцию» для живого показа. Звук плеера изначально выключен.
4. «Только фильм» скрывает чат и сведения о комнате только у вас. «Вернуть панели» возвращает их, не останавливая просмотр у других участников.
5. Для регистрации введите электронную почту, логин и пароль дважды. Значок глаза показывает или скрывает каждое поле пароля. Войти, в том числе в ранее созданный аккаунт, можно по логину и паролю. Комнаты и закладки профиля доступны после входа на другом устройстве. Гостевые комнаты хранятся в браузере. После входа их можно перенести кнопкой под разделом «Мои комнаты». Гостям по приглашению достаточно представиться.
6. При регистрации сайт выдаёт одноразовый резервный код. Сохраните его в менеджере паролей. Для старого аккаунта откройте меню профиля → «Резервный код» и введите текущий пароль. Чтобы восстановить доступ, на форме входа нажмите «Забыли пароль?», введите логин или почту, код и новый пароль. После сброса сайт завершает прежние сеансы и выдаёт новый код.
7. Кнопка с глобусом в шапке переключает язык между русским и английским. Настройка сохраняется в браузере.
8. В «Моих комнатах» значок корзины рядом с названием открывает подтверждение. Ведущий может удалить комнату для всех; приглашение сразу перестанет работать. Участник может убрать комнату из своего списка и при желании вернуться по приглашению.
9. Главная показывает по пять первых мест в каждой из трёх категорий. Кнопка «Все 100» открывает весь рейтинг. Нажатие на оценку ведёт к источнику, на название — к просмотру со своей ссылкой или файлом. В полном рейтинге можно сохранить название в «Наш список».

Прямое видео загружается непосредственно с указанного источника. Для HLS источник должен разрешать CORS. Библиотека профиля хранится на сервере. Для гостевой библиотеки и гостевых прав ведущего ключи сохраняются в текущем браузере. Очистка данных браузера сбрасывает гостевой доступ. Комнаты перестают быть доступны через 7 дней; ссылки-приглашения следует передавать только участникам.

## Хранение и живой показ

По умолчанию Worker хранит загруженные файлы до 32 МиБ частями в существующей D1, с общим резервом 160 МиБ. Для загрузки фильмов до 4 ГиБ создайте бакет в Cloudflare R2 и задайте в настройках **Workers Builds → Build variables** переменную `VMESTE_R2_BUCKET` с его именем. Запустите новую сборку: Vite добавит к production Worker привязку `BUCKET`. Бакет может оставаться приватным. Предпросмотр эмулирует R2 локально. Предел текущей установки возвращает `GET /api/media-options`. Получение файла требует членства в комнате, поддерживает HTTP Range и прекращается после истечения комнаты. Почасовая задача очищает просроченные файлы.

Показ вкладок и больших локальных файлов использует WebRTC. Chrome и Edge на компьютере поддерживают захват вкладки. При прямом соединении используется STUN. Если браузеры не могут соединиться, зритель автоматически переключается на закрытый WebSocket той же комнаты. Кнопка «Смотреть через комнату» сразу включает этот режим, минуя попытки прямой связи. Ведущий использует обычную кнопку показа. Сервер кратковременно пересылает закодированное браузером видео только участникам текущего показа; записи фильма в базе или хранилище не создаются. На компьютере рекомендуется Chrome или Edge. Для закрытого канала в `wrangler.jsonc` объявлен SQLite Durable Object `ROOM_RELAY` (без подписки Realtime, в пределах [квот Workers/Durable Objects](https://developers.cloudflare.com/durable-objects/platform/pricing/)). Для закрытых сетей можно задать секреты Worker `TURN_KEY_ID` и `TURN_API_TOKEN` для [Cloudflare Realtime TURN](https://developers.cloudflare.com/realtime/turn/generate-credentials/). Браузеры получают временные данные доступа для соединения. Если ведущий перезапускает показ в той же комнате, зритель, уже нажавший «Смотреть трансляцию», автоматически подключается к новому сеансу.

## Обычные ссылки Киного

Страницы фильмов и сериалов с `kinogo.my` принимаются в библиотеку и комнаты. Ведущий нажимает «Смотреть в комнате», вставляет прямую ссылку или выбирает «Взять из Киного» с расширением 0.4.0. После проверки первого кадра «Открыть для всех» переключает плеер у участников той же комнаты. Видео загружается у каждого участника от источника; другая сессия может получить отказ из-за срока ссылки, привязки к IP или правил доступа. При необходимости ведущий заменяет ссылку или возвращается к исходной странице Киного. Инструкции по расширению находятся в `/kinogo-extension` и `extension/kinogo/README.md`.

Нажмите «Смотреть на Киного» и запустите фильм. Играющее видео длительностью от 10 минут подключается после 3 секунд стабильного источника. Для коротких роликов и другого плеера доступна кнопка «Подключить это видео» после рекламы. Выбирайте одинаковую версию фильма и перевод. Комната должна оставаться открытой. Поддерживаются `kinogo.my` и плеер `kinogomy.stravers.live`; другие домены требуют отдельной интеграции. Недоступность видео у источника, DRM и ограничения доступа не обходятся.

Расширение не получает токен участника или чат: авторизованные запросы выполняются во вкладке комнаты. Исходная папка и ZIP поддерживают localhost и `https://vmeste.dadvanigeorgii.workers.dev`. При установке или обновлении расширение подключает уже открытые страницы приложения. В окне по значку расширения есть статус, переход к комнате/фильму и «Восстановить связь».

## Развёртывание в Cloudflare Workers

### Что загрузить в репозиторий

Загрузите содержимое папки `vmeste` в корень репозитория: `package.json` должен лежать в корне, рядом с `app`, `components`, `lib`, `db`, `drizzle`, `public`, `extension`, `scripts`, `worker`, `hooks`, `vendor` и конфигурационными файлами. Сохраните скрытую папку `.openai` — её `hosting.json` используется при сборке. `.gitignore` и `package-lock.json` также нужны.

Не загружайте `node_modules`, `dist`, `.next`, `.vinext`, `.wrangler`, `.sites-runtime`, `.git`, `outputs`, `.env*` и `.dev.vars*`. В `.wrangler` находится локальная база, а не исходники; онлайн-база создаётся отдельно. Git уже исключает эти рабочие файлы через `.gitignore`.

### Подготовка D1

1. В Cloudflare откройте **Storage & databases → D1** и создайте базу `vmeste-db`.
2. Скопируйте её **Database ID** и вставьте в `wrangler.jsonc` вместо `00000000-0000-4000-8000-000000000000`. Имя привязки оставьте `DB`. Database ID — идентификатор, не секретный ключ.
3. Сохраните изменение в репозитории. `npm run deploy` проверяет, что вместо заглушки задана настоящая база; перед публикацией применяет ещё не выполненные SQL-миграции из `drizzle`.

### Подключение GitHub к Workers

В **Workers & Pages** создайте **Worker**, подключите репозиторий и укажите:

| Настройка | Значение |
| --- | --- |
| Worker name | `vmeste` (совпадает с `name` в `wrangler.jsonc`) |
| Root directory | Корень репозитория; если загрузили внешнюю папку целиком — `vmeste` |
| Build command | `npm run build` |
| Deploy command | `npm run deploy` |
| Build variable `NODE_VERSION` | `24` |
| Build variable `VMESTE_APP_ORIGIN` | Публичный HTTPS-адрес сайта без пути, например `https://vmeste.your-account.workers.dev` |

Workers Builds устанавливает npm-зависимости по `package-lock.json`. Токен сборки должен иметь права **Workers Scripts: Edit** и **D1: Edit** для вашего аккаунта: deploy-команда не только публикует Worker, но и применяет миграции. Настройте этот токен в Cloudflare; не добавляйте его в репозиторий.

По умолчанию расширение поддерживает localhost и `https://vmeste.dadvanigeorgii.workers.dev`. Для другого адреса задайте `VMESTE_APP_ORIGIN` как переменную **сборки**, запустите новую сборку и скачайте расширение со страницы `/kinogo-extension`.

`npm run build` автоматически собирает ZIP расширения. При заданном `VMESTE_APP_ORIGIN` архив включает разрешение и проверки для конкретного адреса сайта. Исходная установленная локальная копия не меняется. Каждый участник скачивает архив с опубликованного сайта и устанавливает/обновляет расширение в своём браузере.

Папки `dist/client` и `dist/server` создаёт сборка. Публикуется Worker из `dist/server/wrangler.json` вместе со статическими файлами. Дополнительное поле «каталог вывода» для этого сценария не нужно.

Для первого запуска используйте новую D1-базу. `migrations apply` хранит историю и не повторяет применённые миграции. Если вы уже вручную импортировали эту схему в онлайн-базу, сначала согласуйте историю миграций — повторное создание таблиц завершится ошибкой.

Локальные фильмы в библиотеке, комнаты и чат автоматически в онлайн-базу не переносятся. На публичном сайте создайте новую комнату и отправьте друзьям её HTTPS-ссылку.

Официальные инструкции: [Workers Builds](https://developers.cloudflare.com/workers/ci-cd/builds/configuration/), [миграции D1](https://developers.cloudflare.com/d1/reference/migrations/).

## Разработка

Node.js 22.13+ и npm. Проект использует Vinext/React, Cloudflare Workers и D1. Схема находится в `db/schema.ts`, миграции — в `drizzle/`.

```sh
npm ci
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 migrations apply DB --local --config dist/server/wrangler.json --persist-to .wrangler/state
npm run dev
```

Применяйте локальную миграцию только один раз на новую базу. Локальные данные из `.wrangler` не публикуются. Sites применяет миграции к отдельной серверной базе при публикации.

## Обновление рейтингов

Запустите `python scripts/refresh-rankings.py` из рабочего дерева. Скрипт обновляет `lib/rankings.json` только после получения ста записей для каждой категории. Дата снимка и методика доступны на сайте через «Об оценках». В обычном запросе страницы внешние API не вызываются.

Оценки фильмов взяты из записей IMDb в [Викиданных](https://www.wikidata.org/wiki/Property:P444) с русским названием и минимум 10 000 голосов. Сериалы отобраны из [рейтинга TVmaze](https://www.tvmaze.com/shows?Show%5Bsort%5D=7), названия сопоставлены с русскими метками Викиданных. Данные TVmaze доступны по [CC BY-SA](https://www.tvmaze.com/api#licensing). Оценки аниме взяты из [Шикимори](https://shikimori.one/animes/order-by/ranked). Источник каждой позиции доступен по нажатию на оценку.

## Проверки

```sh
npx tsc --noEmit
node --test tests/kinogo-extension.test.mjs
node scripts/package-kinogo-extension.mjs
node tests/integration.mjs
node tests/media-sharing.integration.mjs
npm run build
```

При установленном Playwright и Chrome можно дополнительно выполнить `node tests/share-reconnect.browser.mjs`. Тест задерживает вход зрителя, заменяет показ и проверяет получение новых кадров после ответа 409. Тест `node tests/share-relay.browser.mjs` отключает маршруты WebRTC, проверяет получение настоящих кадров через комнату, поздний вход и закрытие доступа после остановки. Путь к Chrome задаётся через `QA_CHROME`, путь к внешней установке Playwright — через `QA_PLAYWRIGHT`.

Для интеграционных проверок нужен запущенный сервер на `http://127.0.0.1:5173`; другой адрес можно задать через `TEST_BASE_URL`. Проверки создают тестовые комнаты в указанной базе. Проверяются две роли, позднее подключение, общая временная шкала, конкурирующие изменения, чат, вместимость и изоляция библиотек.

Синхронизация использует серверную позицию, время обновления и версию состояния. Клиенты опрашивают сервер примерно раз в секунду, учитывают разницу часов и корректируют локальное воспроизведение. Задержка передачи действий зависит от сети. При обрыве связи интерфейс показывает переподключение; после восстановления состояния сходятся снова. Переключать фильм может только ведущий.
